# AI-보조 IP 창작 웹앱 · 스펙 v1.0

## 제품 비전

**한 줄:** 키워드 하나에서 완결된 웹소설 144화까지, AI와 함께 창작·생산하는 통합 도구.

**차별점:**
- 대부분의 AI 창작 도구는 "글 써주기"에서 멈춘다.
- 이 앱은 **창작의 두 단계**를 명확히 분리하고 각각을 지원한다:
  - **Phase 1** — 아이디어를 세계관으로 자라게 하기 (Genesis Engine)
  - **Phase 2** — 세계관을 실제 회차 원고로 뽑기 (Production Engine)
- 두 단계 사이에 **성경(Bible)** 이라는 확정 문서가 있고, 원고는 이 성경을 배신하지 않게 자동으로 검증된다.
- 상단 대시보드는 **토큰·비용을 실시간**으로 보여줘 창작이 예산·시간과 함께 진행되게 한다.

**목표 사용자:**
- 웹소설·웹툰·드라마 IP를 기획·생산하는 개인 작가·기획자
- 스튜디오·에이전시의 IP 개발 담당자
- 대학·창작학과 (교육용 도구)

## 1. Phase 1 · Genesis Engine

### 1.1 목적

키워드·단편 아이템·이미지 한 장에서 시작해서, AI와의 대화를 통해 세계관을 노드 단위로 자라게 하고, 최종적으로 **성경 문서 3종**을 자동 생성한다.

### 1.2 입력 방식

- **텍스트 입력** — 아이디어 한 줄, 문장, 문단
- **이미지 업로드** — 참조 이미지, 실제 로케이션 사진, 무드보드
- **URL 붙여넣기** — 참고 기사, 웹페이지
- **음성 녹음** (선택) — 자유 브레인스토밍 녹음 → 자동 텍스트화
- **파일 업로드** — 기존 초안, 참고 문헌

### 1.3 세션 유형

세션은 목적별로 구분된다. AI가 세션 유형에 따라 톤과 반응을 조정한다.

| 세션 유형 | 목적 | AI 톤 |
|---|---|---|
| 브레인스토밍 | 자유 확장 | 넓게, 여러 옵션 제시 |
| 방향 잡기 | 구조화 | 구체적, 결정 유도 |
| 검토 | 자체 진단 | 냉정, 구멍 지적 |
| 결정 | 사용자 확정 | 짧게, 확정 확인만 |

### 1.4 노드 관리 시스템

Phase 1의 핵심. 대화 중 등장하는 모든 아이디어가 자동으로 노드가 된다.

**노드 자동 생성 규칙:**
- 사용자 발화에서 새 아이디어·설정·인물·소재가 등장하면 → 새 노드 후보
- AI 응답에서 새 옵션·제안·확장이 등장하면 → 새 노드 후보
- 사용자가 "확정" 시그널(예: "이거로 가자")을 주면 → 노드 상태 확정
- 사용자가 "폐기" 시그널을 주면 → 노드 상태 폐기 (삭제 아님)

**노드 자동 태깅:**
- AI가 태그 후보 3개 제시
- 사용자가 승인/수정

**노드 필드:**
```yaml
node:
  id: N001
  title: "이유 없이 제주를 거부하는 여자"
  tags: [캐릭터, 플롯]
  status: 확정 | 진화중 | 보류 | 폐기
  content: "..."
  parent_nodes: []
  child_nodes: [N009, N011]
  created_at: 2026-08-10T14:32:00
  session_id: sess_abc123
  origin_message_id: msg_xyz789
```

### 1.5 노드 그래프 시각화

- 노드들이 링크로 연결된 지식 그래프 뷰
- 확정 노드 = 진한 색, 진화중 = 중간 색, 폐기 = 회색
- 카테고리별 클러스터링
- 시간축 슬라이더 (창작 궤적 재생)
- 노드 클릭 시 → 원 대화 컨텍스트 표시

### 1.6 성경 자동 편입

노드가 확정 상태가 되면 성경 문서에 자동 편입된다.

**성경 문서 3종:**
1. **기획서(Concept Bible)** — 개요·기획의도·차별점·타겟·인물·시놉시스·비주얼
2. **제작 성경(Production Bible)** — 회사 세팅·꿈 앵커·수치표·편지 전문·좌위 말투·씬 대사·엔딩 컷
3. **창작 로그(Creation Log)** — 노드 목록·진화 궤적·폐기 목록·미결 사항

**편입 규칙:**
- AI가 노드의 성격에 따라 어느 성경의 어느 섹션에 갈지 자동 판단
- 사용자 확인 후 편입
- 편입 후에는 성경 문서에서 원 노드로 역참조 가능

**성경 개정 관리:**
- 문서 편집 시 자동 버전 관리 (v1.0, v1.1...)
- 변경 diff 표시
- 폐기된 이전 문장도 이력에 남음

### 1.7 확장 유도 도구

AI가 사용자에게 능동적으로 확장을 제안한다.

**버튼:**
- "이 노드 확장해봐" — 관련 아이디어 3개 제시
- "이 노드 반대 방향" — 반박·역발상 제시
- "다른 매체라면?" — 웹툰·시나리오 관점에서 재해석
- "이 방향 계속?" — 폐기 vs 유지 결정 유도
- "구멍 찾아줘" — 현재 세계관의 논리적 구멍 지적

### 1.8 완결 조건 판단 (Phase 1 → Phase 2 전환)

**AI 자체 진단 알고리즘:**
- 노드 총 개수와 카테고리 분포 확인
- 성경 필수 섹션 채워짐 여부 확인
- 결정 대기 항목 개수 확인

**임계값 예시** (웹소설 144화 기준):
- 노드 최소 80개 이상
- 카테고리 14개 중 12개 이상 채움
- 성경 3종 필수 섹션 100% 채움
- 결정 대기 5개 이하

**전환 UI:**
- "Phase 1 완결 판정" 버튼
- AI가 자체 진단 리포트 제시
- "부족" 시 어떤 노드가 필요한지 구체적으로 제시
- 사용자 승인 후 Phase 2 활성화

### 1.9 분량 계산기

성경 완성도에 따라 이 재료로 뽑을 수 있는 분량이 얼마인지 실시간 계산.

**출력 예시:**
> 현재 재료로 뽑을 수 있는 분량:
> - 웹소설: 140~150화 (회당 5,000자)
> - 웹툰: 70~80화 (회당 20컷)
> - 드라마: 12부작 (60분 × 12)
> - 영화: 2편 (트릴로지 가능성 있음)

## 2. Phase 2 · Production Engine

### 2.1 목적

Phase 1의 성경을 기반으로 실제 회차 원고를 생산한다. 성경과의 일관성을 자동 검증하고, 매 회 갱신되는 **캐논 트래커**로 장기 일관성을 유지한다.

### 2.2 원고 생산 모드

세 가지 모드 지원. 사용자가 리스크·속도에 따라 선택.

**A. 회차별 (Episode-by-Episode)**
- 1회차 원고 생성 → 사용자 리뷰 → 승인 → 트래커 갱신 → 다음 회차
- 가장 안전. 매 회 검증.
- 권장 리듬: 1일 1화 or 격일

**B. 배치 (Batch)**
- 여러 회차를 한 번에 생성 (2~10화 단위)
- 리뷰 부하 증가하지만 속도 빠름
- 배치 내 회차 간 일관성은 AI가 자체 검증
- 권장: 1부(10~12화)를 한 배치로

**C. 전편 (Full Season) — 실험적**
- 전 144화를 한 번에 생성
- 리스크 최대. 원고 품질 하락 가능성.
- MVP 이후 검토

### 2.3 컨텍스트 계층 로딩 시스템

토큰 무한 팽창 방지의 핵심. 매 회 원고 생성 시 다음 순서로 컨텍스트를 조립한다.

**Level 1 · 항상 로딩 (필수):**
- 기획서 요약 (핵심 5원칙만 발췌 · 약 2,000 토큰)
- 제작 성경 관련 섹션 (해당 회 배경 · 캐릭터 · 로케이션 · 약 4,000 토큰)
- 캐논 트래커 전체 (약 3,000~10,000 토큰)

**Level 2 · 조건부 로딩 (관련 시):**
- 직전 2~3화 원문 (약 15,000 토큰)
- 관련 복선의 심은 화 발췌

**Level 3 · 선택 로딩 (사용자 지정):**
- 특정 과거 회차 원문 (검색으로 지정)
- 특정 씬 (씬 검색)

**로딩 전략:**
- 시스템이 자동으로 Level 1 + Level 2 조립
- 사용자가 Level 3 추가 지정 가능
- 총 토큰 예산 초과 시 경고

### 2.4 캐논 트래커 자동 갱신

원고 완성 시 트래커가 자동 갱신된다.

### 2.5 원고-성경 일관성 검증

원고 생성 후 자동 검증.

**검증 항목:**
- 등장인물이 성경 인물 시트와 일치하는가 (나이·직업·말투)
- 로케이션이 성경 세팅과 일치하는가
- 시간선이 트래커와 일치하는가 (며칠째, 계절, 수위)
- 성경의 "필수 어구"(어머니 편지 문장, 어머니 마지막 대사 등)가 원문과 일치하는가
- 심은 복선이 지시된 화에서 회수되는가

**불일치 발견 시:**
- 원고 하이라이트로 표시
- 원인 표시 (성경 vs 트래커 vs 원고 중 어느 것과 어긋남)
- 세 가지 해결 옵션 제시:
  - 원고 수정
  - 성경 개정
  - 트래커 개정

### 2.6 리비전 관리

- 원고 자동 버전 관리
- diff 뷰
- 특정 버전으로 롤백
- 편집 이력 검색

### 2.7 원고 내보내기

- Markdown / DOCX / EPUB / PDF
- 부별·화별 그룹핑
- 웹툰용 씬 분할 뷰 (실험적)
- 드라마 시나리오 형식 변환 (실험적)

## 3. 대시보드

### 3.1 상시 표시 (헤더)

화면 상단 고정.

- **오늘 토큰 사용:** 245K / 예산 500K
- **총 프로젝트 토큰:** 4.2M
- **예상 잔여 비용 (완결까지):** 약 82,000원
- **현재 진행:** 12/144화
- **성경 버전:** 기획서 v1.2 · 제작 성경 v1.4 · 트래커 v1.53
- **마지막 활동:** 2분 전

### 3.2 상세 대시보드

별도 페이지.

**A. 토큰·비용 상세**
- 회차별 토큰 소비 그래프
- 세션 유형별 (브레인스토밍 vs 원고 생성) 토큰 비율
- 예상 잔여 회차 × 평균 토큰 = 예상 비용 프로젝션
- 이번 달 사용량 vs 예산 (사용자가 예산 설정 가능)

**B. 창작 진행**
- 노드 성장 그래프 (시간별 노드 수)
- 카테고리별 분포 파이차트
- 결정 대기 항목 리스트

**C. 원고 진행**
- 회차별 완성 캘린더
- 회차별 소요 시간
- 리비전 횟수
- 승인 대기 회차

**D. 일관성 대시보드**
- 성경-원고 불일치 경고 (있으면)
- 트래커 미갱신 회차 (있으면)
- 심은 복선 vs 회수 복선 그래프
- 언급되지 않은 채 오래된 캐릭터 (실종 방지)

### 3.3 알림 시스템

**실시간 알림:**
- 토큰 급증 감지 ("이번 회차 토큰이 평균의 200% 초과")
- 컨텍스트 한도 근접 ("컨텍스트 95% 사용, 계층 조정 권장")
- 성경-원고 불일치 감지
- 트래커 미갱신 경고
- 예산 소진 임박

**주간 리포트:**
- 이번 주 진행량
- 예상 완결일
- 창작 활동 하이라이트

## 4. 데이터 모델

### 4.1 관계도

```
User
 └── Project (1:N)
      ├── Session (1:N)              [Phase 1 대화]
      │    └── Message (1:N)
      ├── Node (1:N)                 [Phase 1 노드]
      │    ├── parent_nodes
      │    └── child_nodes
      ├── Bible (1:1)                [3종 문서]
      │    ├── ConceptBible
      │    ├── ProductionBible
      │    └── CreationLog
      ├── CanonTracker (1:1)         [Phase 2 트래커]
      ├── Episode (1:N)              [Phase 2 원고]
      │    ├── Revision (1:N)
      │    └── Approval
      └── Metric (1:N)               [토큰·비용 로그]
```

### 4.2 주요 테이블

**Project**
```sql
- id (PK)
- user_id (FK)
- title
- genre (웹소설·웹툰·드라마·복합)
- target_length (예: 144화)
- phase (1 or 2)
- created_at
- updated_at
```

**Node**
```sql
- id (PK)
- project_id (FK)
- title
- content (text)
- tags (array)
- status (확정·진화중·보류·폐기)
- session_id (FK, nullable)
- origin_message_id (FK, nullable)
- embedding (vector, for semantic search)
- created_at
- updated_at
```

**Bible**
```sql
- id (PK)
- project_id (FK)
- type (concept · production · log)
- version
- content (jsonb, structured sections)
- created_at
- updated_at
```

**CanonTracker**
```sql
- id (PK)
- project_id (FK)
- version
- state (jsonb, 위 §2.4 구조)
- last_updated
```

**Episode**
```sql
- id (PK)
- project_id (FK)
- bu (int, 부)
- hwa (int, 화)
- content (text)
- word_count
- token_used
- cost_krw
- status (draft · reviewed · approved)
- created_at
- approved_at (nullable)
```

**Metric**
```sql
- id (PK)
- project_id (FK)
- event_type (session · episode_gen · revision)
- entity_id (session_id or episode_id)
- input_tokens
- output_tokens
- cost_krw
- created_at
```

### 4.3 벡터 검색

**용도:**
- 노드 간 의미 유사도 검색 ("이 아이디어와 비슷한 게 이미 있나?")
- 원고 씬 검색 ("이 씬과 비슷한 이전 씬 찾아줘")
- 성경 섹션 검색

**저장:**
- Node.embedding (Cohere or OpenAI ada-002)
- Episode.scene_embeddings (씬 단위)

## 6. UX 흐름 (사용자 여정)

### 6.1 새 프로젝트 시작

1. 로그인
2. "새 프로젝트" 클릭
3. 프로젝트 제목·장르·목표 분량 입력
4. Phase 1 세션 자동 시작
5. AI 첫 메시지: "어떤 이야기를 시작할까요? 키워드·이미지·문장 무엇이든 좋습니다."

### 6.2 Phase 1 진행

1. 사용자 입력 → AI 응답 → 노드 자동 생성 (사이드바에 표시)
2. 노드 확장 버튼으로 방향 유도
3. 우측 패널에 성경 자동 채워지는 것을 실시간 확인
4. 대시보드 상단: 토큰·비용·노드 수 표시
5. 어느 시점 AI 판단: "이 재료로 X 분량 뽑을 준비됨"
6. 사용자가 "Phase 2 진입" 클릭

### 6.3 Phase 2 진행

1. Phase 2 화면 전환
2. 성경 3종 확정 · 캐논 트래커 초기화
3. "1-1화 생성" 클릭
4. AI가 계층 로딩(성경+트래커+직전화) 후 원고 스트리밍
5. 원고 완성 → 자동 일관성 검증 → 사용자 리뷰
6. 승인 시 트래커 자동 갱신, 다음 화 활성화
7. 수정 필요 시 하이라이트된 부분 편집 or 성경/트래커 개정

### 6.4 회차 관리

- 좌측 사이드바: 회차 트리 (1부 > 1-1화, 1-2화...)
- 각 회차: 상태 표시 (draft · reviewed · approved · locked)
- 우측 패널: 해당 회차 트래커 스냅샷
- 하단: 관련 성경 섹션 미리보기

### 6.5 일관성 확인

- 별도 페이지 "일관성 대시보드"
- 심은 복선 vs 회수 상태 그래프
- 인물별 마지막 등장 시점
- 불일치 경고 리스트

## 8. 확장 가능성

### 8.1 B2C IP 창작 도구 시장

- 웹소설 작가·기획자 대상 구독 서비스
- 대학·창작학과 교육용 라이센스
- 아마추어 창작자 커뮤니티

### 8.2 B2B 스튜디오 라이센스

- 스튜디오·에이전시가 소속 작가에게 지급
- 브랜드 화이트라벨 (스튜디오 로고)
- IP 관리·아카이빙 자산

### 8.3 IP 마켓플레이스 (V3+)

- 사용자가 완성한 IP를 마켓플레이스에 공개
- 편성사·제작사가 검색·구매
- 창작자에게 로열티

### 8.4 파운데이션 모델 파인튜닝 (장기)

- 앱 내 창작 데이터를 (사용자 동의 하에) 학습 데이터로 활용
- 창작 특화 파운데이션 모델 개발
- API로 재판매

### 8.5 창작 프로세스 자체가 콘텐츠 (메타)

- 사용자의 창작 로그 자체를 팬들이 열람 가능한 부속 콘텐츠로
- 도깨비 김은숙 작가 노트 같은 것을 앱이 자동 생성
- IP 팬덤 형성 도구
